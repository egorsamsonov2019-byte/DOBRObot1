# Бот-помощник ГУАП для сообщества ВКонтакте

Бот отвечает на 91 частый вопрос из базы `ГУАП_все_вопросы.docx`, понимает вопросы своими словами, присылает скриншоты-инструкции. Передачи живому специалисту нет: если ответа в базе нет, бот предлагает переформулировать вопрос или выбрать раздел. Логика диалога описана в [`SCENARIO.md`](SCENARIO.md).

## Состав проекта

| Файл | Назначение |
|---|---|
| `bot.py` | Основной код: сценарий диалога, клавиатуры, отправка сообщений |
| `faq_engine.py` | Поиск по базе (понимает падежи, опечатки, синонимы) |
| `texts.py` | Все тексты и подписи кнопок. **Правьте здесь** |
| `data/faq.json` | База вопросов и ответов (получена из вашего .docx) |
| `data/images/` | 20 скриншотов к ответам |
| `convert_docx.py` | Пересборка базы из обновлённого .docx |
| `.env.example` | Шаблон настроек (токен, ID сообщества, администраторы) |
| `Dockerfile`, `docker-compose.yml`, `guap-bot.service` | Варианты запуска на сервере |

## Шаг 1. Настройте сообщество ВКонтакте

Нужны права администратора сообщества. Все пункты находятся в **Управление** (раздел «Управление» → шестерёнка в правой колонке на сайте).

1. **Включите сообщения.** Управление → **Сообщения** → «Сообщения сообщества» → **Включены**.
2. **Включите возможности для ботов.** Там же: **Настройки для бота** → «Возможности ботов» → **Включены**. Поставьте галочку **«Разрешить добавлять сообщество в беседы»** только если нужно, для личных вопросов она не требуется.
3. **Кнопка «Начать».** В том же разделе включите «Кнопка „Начать“»: при первом входе пользователь увидит её, нажмёт, и бот пришлёт меню.
4. **Приветствие (по желанию).** Сообщения → «Приветствие»: короткий текст «Нажмите „Начать“ и выберите раздел».
5. **Узнайте ID сообщества.** Управление → Настройки → **Адрес сообщества**. Если адрес вида `vk.com/club123456789`, то ID — `123456789`. Если у сообщества короткое имя, ID виден в Управление → Дополнительно → Работа с API (поле «ID сообщества» внизу страницы).

## Шаг 2. Получите ключ доступа (токен)

1. Управление → **Дополнительно** → **Работа с API** → вкладка **Ключи доступа** → **Создать ключ**.
2. Отметьте права:
   - ✅ **Разрешить приложению доступ к сообщениям сообщества**
   - ✅ **Разрешить приложению доступ к фотографиям сообщества** (нужно для отправки скриншотов)
3. Подтвердите действие кодом из SMS и скопируйте ключ (строка вида `vk1.a.…`).

> ⚠️ Ключ равен паролю от сообщества. Не публикуйте его, не отправляйте в чатах и не храните в открытых репозиториях. Если ключ утёк, удалите его на той же странице и создайте новый.

## Шаг 3. Включите Long Poll API

На той же странице **Работа с API** → вкладка **Long Poll API**:

1. Переключатель **Long Poll API → Включён**.
2. Версия API: выберите **последнюю доступную** (подойдёт любая от 5.131).
3. Вкладка **Типы событий** → отметьте **Входящее сообщение** (раздел «Сообщения»).

Без этого бот запустится, но ничего не получит.

## Шаг 4. Запустите бота

Бот работает как программа, которая должна быть включена постоянно. Выберите один из вариантов.

### Вариант A. Быстрая проверка на своём компьютере (Windows / macOS / Linux)

Нужен Python 3.10 или новее ([python.org](https://www.python.org/downloads/)).

```bash
cd guap_bot
python -m venv venv
# Windows:        venv\Scripts\activate
# macOS / Linux:  source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # Windows: copy .env.example .env
```

Откройте `.env` в блокноте и заполните:

```
VK_TOKEN=ваш_ключ_из_шага_2
VK_GROUP_ID=123456789
```

Запуск:

```bash
python bot.py
```

В консоли появится «Бот запущен, слушаю сообщения сообщества…». Напишите сообщество в личные сообщения и нажмите «Начать». Пока окно закрыто или компьютер выключен, бот не отвечает, поэтому для постоянной работы нужен сервер (варианты B и C).

### Вариант B. Постоянная работа на VPS (Ubuntu 22.04 / 24.04)

Подойдёт любой недорогой виртуальный сервер (1 ядро, 512 МБ–1 ГБ памяти достаточно).

```bash
sudo apt update && sudo apt install -y python3 python3-venv python3-pip unzip
sudo adduser --system --group botuser
sudo mkdir -p /opt/guap_bot && sudo chown botuser:botuser /opt/guap_bot
# загрузите архив на сервер (scp или через панель хостинга) и распакуйте:
sudo -u botuser unzip guap_bot.zip -d /opt/ && cd /opt/guap_bot
sudo -u botuser python3 -m venv venv
sudo -u botuser venv/bin/pip install -r requirements.txt
sudo -u botuser cp .env.example .env && sudo -u botuser nano .env     # впишите токен и ID
sudo cp guap-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now guap-bot
```

Проверка и логи:

```bash
sudo systemctl status guap-bot          # должно быть active (running)
journalctl -u guap-bot -f               # живой журнал; выход — Ctrl+C
sudo systemctl restart guap-bot         # перезапуск после правок
```

Служба сама стартует после перезагрузки сервера и перезапускается при сбоях.

### Вариант C. Docker (если на сервере уже есть Docker)

```bash
cp .env.example .env && nano .env       # впишите токен и ID
docker compose up -d --build
docker compose logs -f                  # журнал
```

### Вариант D. Облачные платформы для приложений

Подойдёт любая платформа, которая запускает Python-процессы или Docker-контейнеры без входящего порта (бот сам подключается к ВК, веб-адрес ему не нужен). Загрузите проект, укажите команду запуска `python bot.py` (или используйте `Dockerfile`) и задайте две переменные окружения: `VK_TOKEN`, `VK_GROUP_ID`. Выбирайте тариф, где процесс работает круглосуточно, а не «засыпает» без запросов.

## Шаг 5. Проверьте работу

Напишите сообщество от своего аккаунта и пройдите проверку:

- [ ] «Начать» или «Привет» → приходит приветствие и 8 кнопок разделов
- [ ] Раздел «Здоровье» → кнопка «27» → приходит ответ **и скриншот**
- [ ] «потерял банковскую карту» → бот предлагает вопросы 78/79
- [ ] «погода в питере» → «Не нашёл подходящий ответ» и предлагает меню
- [ ] Раздел «Здоровье» → «39» → приходит сравнение абилитации и реабилитации

## Как обновлять базу знаний

**Способ 1 (рекомендуется): отредактировать .docx и пересобрать базу.** Таблица должна сохранить структуру: колонка № · Вопрос · Ответ · (необязательно) дополнение; строки-заголовки разделов. Картинки вставляйте в ячейку ответа.

```bash
python convert_docx.py "ГУАП_все_вопросы.docx"
sudo systemctl restart guap-bot        # или: docker compose restart
```

**Способ 2: править `data/faq.json` вручную** (поля `q` — вопрос, `a` — ответ, `images` — файлы из `data/images/`). Чтобы заменить текст ответа в самом конвертере, добавьте его в словарь `OVERRIDES` в `convert_docx.py` (так сделан ответ №39).

После правок перезапустите бота.

Ориентируйтесь на журналы `logs/unanswered.csv` (что спрашивают, а ответа нет) и `logs/feedback.csv` (где ставят 👎): эти данные подскажут, что добавить или переписать.

## Настройки, которые стоит изменить

- **Тексты и кнопки:** `texts.py` (приветствие, подписи, эмодзи разделов).
- **Чувствительность поиска:** в `bot.py` константы `CONFIDENT = 0.60` (когда отвечать сразу) и `SUGGEST = 0.25` (когда предлагать варианты). Больше значение — бот осторожнее.
- **Синонимы:** в `faq_engine.py` словарь `SYN`. Если замечаете, что люди пишут «биржа» вместо «ЦЗН», добавьте пару слов.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Бот запущен, но молчит | Не включён Long Poll или не отмечено событие «Входящее сообщение» (шаг 3); не включены сообщения сообщества (шаг 1) |
| `KeyError: 'VK_TOKEN'` | Не создан файл `.env` или он лежит не в папке проекта |
| `[5] User authorization failed` / `invalid access_token` | Неверный или удалённый ключ: создайте новый (шаг 2) |
| `[15] Access denied` при отправке картинок | У ключа нет права на фотографии: создайте ключ с галочкой «фотографии» |
| `[901] Can't send messages for users without permission` | Пользователь не писал сообществу первым или запретил сообщения: это ограничение ВК |
| `[100] group_id is undefined/invalid` | Неверный `VK_GROUP_ID` (нужны только цифры, без минуса и `club`) |
| Кнопки не показываются | Сообщество должно быть с включёнными возможностями ботов (шаг 1, пункт 2) |

## Безопасность и персональные данные

- Токен хранится только в `.env` (файл исключён из git через `.gitignore`).
- В журналах `logs/*.csv` хранятся **числовые ID пользователей ВК** и тексты их вопросов. Пользователи этой аудитории относятся к уязвимой группе: ограничьте доступ к серверу и папке `logs/`, не передавайте журналы третьим лицам и согласуйте хранение с ответственным за персональные данные в ГУАП (152-ФЗ). Если журналы не нужны, удалите вызовы `log_csv` в `bot.py`.
- Бот не запрашивает паспортные и иные личные данные. Пользователям лучше не присылать их в диалог, добавьте об этом строку в приветствие (`texts.py` → `WELCOME`).
